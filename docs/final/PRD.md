## 1. 产品定位

**RunCoach 是一个"地图 + 对话"的 AI 跑步教练 Web 应用**，把跑者高频的两件事收进同一个界面：

1. **跑前**：用自然语言生成一条贴合真实路网的跑步路线（环线 / 点到点，可选越野或路跑），预览后导出 GPX。
2. **跑后**：上传真实 FIT / GPX / JSON 运动文件，在地图上回放轨迹，由 AI 基于解析出的真实数据做训练复盘与对比。

核心叙事：**从"自然语言意图"到"可执行路线 / 可解释训练洞察"的闭环**，且全程让真实路网 API 与本地解析兜底数据、AI 只负责理解与解释，从结构上抑制幻觉。

### 1.1 Suunto 业务场景结合

RunCoach 对应 Suunto 用户"运动前规划 → 运动中记录 → 运动后复盘"链路里的**前后两端 AI 化**：

| Suunto 现有链路 | 痛点 | RunCoach 的 AI 增益 |
|---|---|---|
| 跑前在 App 手动画路线、试距离、选路面 | 手动、费时、不懂哪条贴合目标距离 | 一句话生成指定公里数的真实路线，区分越野/路跑，导出 GPX 可同步进 Suunto App / 手表 |
| 跑后在 App 看一堆配速/心率曲线 | 数据多但缺解释，普通用户读不懂 | 上传手表导出的 FIT，AI 用人话复盘强度、配速、心率、分段与下次建议 |

可作为 Suunto 生态内"AI 路线规划"与"AI 训练解读"两个能力的原型，导出的 GPX 即对接设备生态的标准交付物。

## 3. 信息架构与界面

单页应用，**地图永远是主区，所有控件是叠加层**。

```
┌────────────────────────────────────────────┐
│                                      [⚙设置] │  ← 右上角仅设置齿轮
│                                              │
│              满屏地图 (MapLibre)             │
│        路线/轨迹/起点针/跑者点 渲染于此       │
│                                  ┌─────────┐ │
│                                  │路线预览卡│ │  ← 生成路线后出现
│                                  └─────────┘ │
│        ┌──────────────────────────┐          │
│        │   引导卡片（按需弹出）     │          │  ← 地形卡/起点卡 居中
│        └──────────────────────────┘          │
│   ┌──────────┐                                │
│   │ 对话栏    │      [底部回放条/确认条]        │
│   │(落地→左下)│                                │
│   └──────────┘   [＋ 输入框 ↑]                │
└────────────────────────────────────────────┘
```

- **落地态**：地图满屏，对话框居中悬浮底部（仿 Claude/GPT）。
- **工作态**：首次发送后对话框以动画收到**左下角**成为聊天栏；地图主区按场景渲染路线或回放。
- 聊天气泡：用户/AI 各有头像；AI 回复**渲染为带排版的富文本**（标题/加粗/列表/代码），不显示 Markdown 原始符号。

> 说明：v1 曾在右上角放"当前位置/地图选点/地名"三段切换器，**v2 已移除**，改为下文 §5 的 AI 引导式卡片流程。

## 4. 功能范围

### 4.1 对话入口与设置

| 功能 | 行为 | 验收标准 | 涉及模块 |
|---|---|---|---|
| 满屏地图 | MapLibre + MapTiler `streets-v2` 底图，默认定位当前位置 | 打开页面地图可见、无空白应用；授权定位后相机飞向用户位置 | `map/MapView.tsx`、`map/layers.ts` |
| 对话框 | 输入自然语言；`＋` 上传 FIT/GPX/JSON | 回车/点击发送触发 AI；`＋` 可选文件；**中文输入法组词时回车不误发**（`isComposing` 守卫） | `chat/Composer.tsx`、`chat/ChatDock.tsx` |
| AI 回复渲染 | 富文本渲染（react-markdown） | 回复无可见 `##`/`**` 等原始符号 | `chat/ChatDock.tsx` |
| LLM 设置 | 右上角齿轮：Provider(Kimi/DeepSeek)、Model、API Key | 可输入、显示/隐藏、**测试 key 即时显示 ✓/✗**、保存到 localStorage | `settings/SettingsGear.tsx`、`llm/provider.ts` |

### 4.2 路线生成（核心）

| 功能 | 行为 | 验收标准 | 涉及模块 |
|---|---|---|---|
| 环线生成 | 起点 + 目标公里 → 回到起点的真实路网环线 | 必须调用 `generate_loop_route`，不得编造坐标；实际距离落在目标 ±5%（≤3 轮迭代逼近） | `agent/tools.ts`、`routing/ors.ts` |
| 点到点路线 | 起点 + 终点 → 真实路网路线 | 调用 `generate_point_to_point_route`；地名可先 `geocode_place` | 同上、`routing/geocode.ts` |
| 越野 / 路跑分流 | 越野→ORS `foot-hiking`（偏山路步道）；路跑→`foot-walking`（道路） | 说"越野/trail"得到偏山路路线；"路跑/road"得到走道路路线 | `routing/ors.ts`(profile) |
| 距离/爬升展示 | 右上路线预览卡显示**实际**距离与累计爬升 | 如实显示实际 km，不承诺"正好" | `app/App.tsx`(route-card) |
| 换一条 | 同距离换 seed 生成不同走法 | 点"换一条"重新请求并刷新路线 | `app/App.tsx`、`routing/ors.ts` |
| GPX 导出 | 当前路线导出为 GPX | 文件名 `runcoach-route.gpx`；坐标顺序正确；**每点含 `<ele>` 高程**，外部工具可见爬升曲线 | `export/gpx-export.ts` |

### 4.3 训练上传与复盘

| 功能 | 行为 | 验收标准 | 涉及模块 |
|---|---|---|---|
| 文件上传 | FIT / GPX / JSON | 选择后解析为 `Run`，进入回放态 | `runs/fit.ts`、`runs/gpx.ts`、`runs/json.ts` |
| 地图轨迹 | 展示真实轨迹并自动 `fitBounds` 到视野 | 不在默认城市也能看到轨迹 | `map/layers.ts`(fitToCoords) |
| 回放条 | 按距离进度移动跑者点，显示实时配速/心率/距离 | 拖动进度条，地图 runner marker 更新 | `app/ReplayBar.tsx` |
| 数据摘要 | 距离、用时、配速、心率、功率、步频、高程、分段检查点 | 缺失指标为 `undefined`/`--`，不伪造 | `analysis/digest.ts` |
| AI 复盘 | 上传后自动发"请复盘"，AI 据摘要解读 | 回复引用解析摘要与关键检查点，缺失数据明说 | `agent/coach.ts`、`agent/tools.ts` |
| A/B 对比 | 对比两份已上传训练 | 调用 `compare_runs`，输出差异解读 | `analysis/digest.ts` |

## 5. AI 引导式交互（起点 + 地形）

**触发**：AI 识别到"要生成跑步路线"的意图后，先盘点缺什么——**缺什么才弹什么卡，能从原话推断的不再问**。

### 5.1 流程

```
用户："来一条 5 公里环线"
  └─ AI 缺地形 → 调 ask_run_terrain → 弹「地形卡」🏔越野 / 🛣路跑
       └─ 用户选越野
  └─ AI 缺起点 → 调 ask_start_point → 弹「起点卡」📍当前位置 / 🗺手动选点
       ├─ 当前位置 → 用浏览器定位坐标（定位被拒 → 卡片提示并引导手动）
       └─ 手动选点 → 地图光标变十字 → 提示条「在地图上点选起点…（取消）」
                     → 点图落临时针 → 确认条「把起点设在这里？✓确定 / ✗取消」
  └─ 地形+起点齐 → 调 generate_loop_route(start, 5, terrain=trail) → 渲染 + 预览卡
```

- **能推断就跳过**：说"从我当前位置来条越野5公里环线" → 地形与起点都齐，**零卡片直接生成**；说"从人民广场出发" → AI 用 `geocode_place` 取坐标，不弹卡。
- **取消传播**：任一卡片取消 → 对应工具回 `{cancelled:true}` → AI 礼貌停止、不生成路线。

### 5.2 Agent 角色与工具集

系统提示词将 AI 定义为"严谨的跑步训练教练兼数据分析师"，**严格限定跑步领域**；越界（写代码/查天气/闲聊）一句话礼貌拒绝且不调任何工具。

| 工具 | 用途 |
|---|---|
| `generate_loop_route` | 真实路网环线（带 terrain→profile、距离逼近） |
| `generate_point_to_point_route` | 真实路网点到点 |
| `geocode_place` | 地名 → 坐标 |
| `ask_run_terrain` | 地形未知时弹地形卡，返回 `{terrain}` 或 `{cancelled}` |
| `ask_start_point` | 起点未知时弹起点卡，返回 `{start}` 或 `{cancelled}` |
| `analyze_run` | 取已上传训练摘要 |
| `compare_runs` | 对比两份训练 |

### 5.3 约束

- 生成路线必须调用工具，AI 不自编 GPS 坐标；实际距离/爬升以工具返回为准。
- 训练分析只基于已上传文件解析出的结构化摘要。
- 生成前须确定地形与起点；能从用户原话推断就用，缺失才弹卡；已知不再问。
- 缺 API Key、路由失败、文件解析失败、定位被拒——错误对用户可见、可读、可重试。

## 6. 数据流

### 6.1 路线生成

```
用户输入(+当前定位上下文) → useChatAgent.send
  → llm/provider 带工具 schema 调 Kimi/DeepSeek
  → 模型按需 tool_call：ask_run_terrain / ask_start_point（弹卡，Promise 等用户）
  → 模型 tool_call：generate_loop_route{start, distance_km, terrain}
  → routing/ors：terrain→profile，ORS round-trip，±5%/3 轮逼近，保留每点高程
  → 工具结果回模型 → 模型自然语言回复 ─→ 聊天栏富文本
                                     └─→ map 画线 + 起点针 + fitBounds + 预览卡
  → 「下载 GPX」→ export/gpx-export（写 <ele>）  或  「换一条」→ 换 seed 重跑
```

### 6.2 训练复盘

```
＋上传 → 按扩展名解析(fit/gpx/json)→ Run → 存入 runs Map
  → map 画轨迹 + fitBounds；ReplayBar 可拖动
  → 自动 send「请复盘」(带 run_id) → 模型可调 analyze_run 取摘要 → 富文本复盘
```

## 7. 外部服务与配置

| 服务 | 作用 | 配置 |
|---|---|---|
| MapTiler | 底图瓦片、地名搜索、高程 | `.env.local` 的 `VITE_MAPTILER_KEY`（构建期） |
| OpenRouteService | 真实路网路由：`foot-walking`/`foot-hiking`，环线 round-trip | `.env.local` 的 `VITE_ORS_KEY`（构建期，免费额度足够 Demo） |
| Kimi / DeepSeek | AI 对话 + 工具调用（OpenAI 兼容） | 应用内右上角齿轮，存浏览器 localStorage（运行期） |

> 说明：MapTiler 路由 API 仍在 beta，故路由由 ORS 承担；MapTiler 仅负责底图/地名/高程。

## 8. 错误处理矩阵

| 场景 | 表现 |
|---|---|
| 浏览器定位被拒/失败 | 起点卡提示"定位不可用，请改用手动选点"，自动引导手动 |
| ORS 找不到路线（水里/无路网/越野无山路） | 聊天如实说明，建议换起点或改路面 |
| 距离 3 轮未达标 | 返回最接近的一条，预览卡标实际公里 |
| LLM key 缺失/失效 | 发送前拦截或测试返回 ✗ 原因，提示去齿轮配置，不静默 |
| 越界提问 | AI 一句话礼貌拒绝，不调工具 |
| 文件解析失败 | 聊天出错误气泡，不影响已有状态 |
| 卡片取消 | AI 礼貌停止，不生成 |

## 10. 使用路径

### 10.1 跑前 · 生成路线
1. 打开页面，地图加载、定位到当前位置。
2. 右上齿轮配置并**测试** LLM key（✓ 后保存）。
3. 对话框输入，例如：`帮我从当前位置生成一条 6 公里的城市慢跑环线`。
4. 按引导卡片选地形/起点（或一句话说全跳过卡片）。
5. 查看地图路线、实际距离、累计爬升；不满意点"换一条"。
6. 点"下载 GPX"，得到可同步进运动设备生态的路线文件。

### 10.2 跑后 · 训练复盘
1. 点对话框 `＋` 上传真实 FIT 文件。
2. 查看地图轨迹与底部回放条，拖动看配速/心率/距离变化。
3. 阅读 AI 自动复盘；如需对比，再传一份并让 AI 对比。
